# Báo cáo thực nghiệm ngày 25/08/2026: Reproduction FTAL lịch sử và Top-hat

## 1. Mục tiêu

Báo cáo này ghi lại việc xác định và sửa một semantic drift trong Factorized TAL (FTAL), sau đó chạy lại đúng hai ablation cần thiết:

1. `Top-hat + plain FTAL legacy`.
2. `Top-hat + GAP + FTAL legacy`.

Mục tiêu trước đó là kiểm tra tương tác giữa input cue top-hat, GAP và FTAL. Các kết quả top-hat chạy với FTAL `current` trước đây không được dùng để kết luận interaction với historical winner, vì chúng không dùng cùng semantics FTAL.

## 2. Protocol chung

- Dataset: LEVIR-Ship fixed split, split seed `42`.
- Input: RGB normalized, cue được tính bên trong model sau augmentation.
- Architecture: YOLOv8n-P2, chỉ thay đổi stem/cấu hình attention được nêu trong từng variant.
- Image size: `512`.
- Batch size: `8`.
- Epochs: `100`.
- Early stopping: tắt, `patience=0`.
- Training seed: `42`.
- NMS IoU: explicit `0.5`.
- Checkpoint báo cáo: `best.pt`.
- FTAL: `tau=0.75`, `kappa=1.5`, `lambda=0.5`, `s_max=32`, warmup `5 -> 15`, P2-only.

## 3. Phát hiện semantic drift trong FTAL

### 3.1. Historical implementation

Historical winner được train tại commit `a68b00e`. Với mỗi nhóm positive của một GT, code dùng chính TAL target score `q`:

```python
q = target_scores[b, group]
u_max = q.max().clamp_min(1e-12)
q_new = (
    u_max.pow(tau)
    * (q / u_max).clamp(0, 1).pow(kappa)
)
q_final = q + lam * (q_new - q)
```

`target_scores` được tạo từ TAL overlap dùng CIoU. Vì vậy ceiling lịch sử là `q.max()` của TAL target score, không phải một IoU được recompute riêng.

### 3.2. Current refactored implementation

Sau commit `28ac7cc`, implementation được refactor thành:

```python
q_score = q.sum(-1)
q_max = q_score.max()
u_max = u.max()
r = q_score / q_max
q_new_score = u_max.pow(tau) * r.pow(kappa)
```

Trong đó `u` được recompute bằng plain IoU (`CIoU=False`). Đây là một objective khác:

```text
historical: q_max^tau * (q / q_max)^kappa
current:    max(IoU)^tau * (q_score / q_max)^kappa
```

Do đó các run không set `factorized_tal_mode` sau refactor mặc định dùng `current` và không thể so sánh trực tiếp với historical winner.

### 3.3. Cách sửa

Đã thêm mode explicit:

```yaml
factorized_tal_mode: legacy
```

Mode này copy đúng historical semantics, dùng `q.max()` và không dùng recomputed IoU ceiling. Mode `current`, `mass_preserve`, `geometry` và `agreement_gate` vẫn giữ nguyên để không làm thay đổi các experiment target-mode khác.

3. Top-hat clean runs phải dùng `InputCueConv(top_hat)` và explicit no-GGCF config.
4. Mọi run phải ghi mode vào `args.yaml` và `experiment_manifest.json`.
