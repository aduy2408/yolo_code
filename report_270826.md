# LEVIR Evidence Branch Ablation Report

**Date:** 2026-08-26 to 2026-08-27  
**Dataset:** LEVIR Ship  
**Task:** P2-only small-object detection with Factorized TAL  
**Purpose:** Measure whether the evidence branches still help when the final `ChannelAttention(GAP)` block is removed.

## 1. Experimental question

The original evidence-branch design was:

```text
YOLOv8n backbone/FPN -> P2 -> evidence branch -> ChannelAttention(GAP) -> Detect(P2-only)
```

The first matrix used this canonical design. Because `ChannelAttention` performs global average pooling, a second matched matrix was trained with `ChannelAttention` removed. The no-GAP matrix isolates the contribution of the evidence features from the contribution of the GAP-based channel reweighting.

The comparison is not a redesign of Ultralytics. Both matrices use the same YOLOv8n/P2 pipeline, training split, seed, TAL settings, epoch budget, evaluation procedure, and upload contract. The only intended architectural difference is the presence or absence of `ChannelAttention`.

## 2. Implemented approaches

### 2.1 Gradient-isolated evidence branch

File: `ultralytics/nn/modules/evidence.py`

The branch receives the original RGB image through a small stem and produces an 8-channel evidence tensor:

```text
RGB -> Conv(stride=2) -> Conv(stride=2) -> light C2f -> E8
                                                   |
                                                   +-> auxiliary heatmap head
```

For `isolated_evidence8`, the detection path receives `detach(E8)`, while the auxiliary heatmap head receives the non-detached tensor. Therefore the detection loss cannot backpropagate into the evidence tensor, while the auxiliary heatmap loss can still train the evidence branch.

The matched capacity control, `extra8_joint`, uses the same 8-channel branch with detection gradients enabled and auxiliary supervision disabled.

### 2.2 Scale-disappearance evidence branch

The branch uses real intermediate backbone features rather than the raw image:

```text
backbone P2 (32 ch) -> 1x1 projection -> fine feature F (16 ch)
backbone P3 (64 ch) -> 1x1 projection -> upsample -> coarse feature C (16 ch)
                                      F - C and |F - C|
                                      -> Conv/C2f formation -> E8
```

The source backbone features are detached by default. The formed E8 feature is not detached before concatenation with the final P2 feature. This prevents an additional evidence gradient path from changing the backbone during the primary ablation.

### 2.3 Resolution-aware evidence branches

Version 1 uses only resolution degradation as the augmentation state. The transform stores the final image scale in `labels["resolution_scale"]`. The augmentation-aware branch predicts normalized severity and applies a small FiLM conditioning step to the evidence tensor:

```text
RGB -> evidence stem -> E_base8 -> GAP/MLP -> predicted resolution severity
                              |
                              +-> FiLM conditioning -> E8
```

The conditioned variant receives `SmoothL1(predicted_scale, target_scale)` with `aug_state_gain=0.1`. The extra-capacity control receives the same resolution augmentation but has no conditioning loss.

The resolution variants explicitly pin the canonical Mosaic/RandomPerspective path with:

```yaml
resolution_enabled: true
mosaic_postprocess_enabled: true
resolution_min: 0.65
resolution_max: 1.0
```

This avoids confounding the architecture comparison with an accidental switch from canonical Mosaic augmentation to a LetterBox-only path.

### 2.4 No-GAP model definitions

Dedicated no-GAP YAML files were created rather than mutating the original configs in place:

- `yolov8n_p2_extra8_joint_nogap.yaml`
- `yolov8n_p2_gradient_isolated_evidence_nogap.yaml`
- `yolov8n_p2_scale_disappearance_evidence_nogap.yaml`
- `yolov8n_p2_resolution_conditioned_evidence_nogap.yaml`

Each config removes `ChannelAttention`. Detect remains P2-only. The final Detect source is layer 19 for the image-evidence variants and layer 20 for the scale-disappearance variant.

## 3. Training and evaluation protocol

Runner:

```text
train_all_levir_yolov8n_p2_evidence_branches_nogap.py
```

Fixed settings for every variant:

```yaml
epochs: 100
patience: 0
seed: 42
imgsz: 512
batch_size: 8
NMS IoU: 0.5
factorized_tal_target: true
factorized_tal_mode: legacy
factorized_tal_tau: 0.75
factorized_tal_kappa: 1.5
factorized_tal_lambda: 0.5
factorized_tal_s_max: 32
factorized_tal_p2_only: true
factorized_tal_warmup_start: 5
factorized_tal_warmup_end: 15
```

The five no-GAP variants were trained sequentially:

1. `extra8_joint_nogap`
2. `isolated_evidence8_nogap`
3. `resolution_conditioned8_nogap`
4. `resolution_extra8_nogap`
5. `scale_disappearance8_nogap`

The workflow was launched through `python -m utils.marimo_ops launch` from the connected Marimo runtime. The shared workflow required the exact checkout, `MARIMO_TRAIN_WORKFLOW=1`, global-kernel `HF_TOKEN`, the requested dataset root, and the fixed training parameters before launch.

## 7. Conclusions

1. Removing `ChannelAttention(GAP)` reduced test mAP50 for every matched variant. The reduction ranged from 2.19 to 5.30 percentage points.
2. Removing GAP reduced test mAP50-95 for every variant. Therefore GAP is not merely an unused capacity increase. It provides useful channel aggregation/reweighting for the P2 evidence features.
3. `resolution_conditioned8` remained the best approach within both matrices by mAP50. Its no-GAP score was 0.7838, but the GAP version reached 0.8237.
4. `isolated_evidence8` suffered the largest no-GAP degradation, suggesting that detached evidence features particularly depend on downstream channel selection to be useful for detection.
5. `scale_disappearance8` was the least sensitive to removing GAP, but it still did not beat the GAP baseline.
6. The current evidence supports retaining the canonical `ChannelAttention(GAP) + P2-only Detect + Factorized TAL` design. No-GAP should be treated as a negative ablation, not the preferred architecture.

## 8. Reproducibility notes and safeguards

- GAP and no-GAP use separate YAML files and separate run roots.
- The no-GAP runner fails closed if a config contains `ChannelAttention`, uses a non-P2-only Detect source, or enables resolution augmentation without the canonical Mosaic postprocess setting.
- The runner rejects epochs other than 100, patience other than 0, or seeds other than 42.
- Training is only launched through `utils.marimo_ops`; direct invocation without the Marimo workflow marker and HF authentication is rejected.
- Each variant must pass local artifact checks and remote upload verification before the matrix advances.
- The old append-only logs and historical tracebacks are not used as current failures. Current failure checks are scoped to the active launch and current run root.
